Afterclass

Functionality and architecture guide · NIIT University launch · 26 August 2026

Purpose: Afterclass is an anonymous verified-student platform. NIIT University is the first campus. Students verify with @niituniversity.in, use anonymous aliases, join a campus chat, and will be able to create or join activity plans.

Student flow

  1. Student enters NIIT email. The server accepts only active campus domains.
  2. The API creates a six-digit cryptographic OTP, stores only an HMAC hash, expires it after ten minutes, and limits requests.
  3. Successful verification creates/restores an anonymous account and sets an HTTP-only JWT cookie.
  4. Campus chat loads the latest 50 Postgres messages, then opens an authenticated Socket.IO connection.
  5. Messages are capped at 500 characters, rate-limited to 20/minute, filtered, persisted, and broadcast in real time.
  6. A message report sends a message ID; the server derives the internal target account so client code does not select a user ID.

Privacy and security

  • Emails and internal account IDs are not public profile data.
  • JWTs include subject, session version, issuer, audience, and expiry only.
  • Logout increments session version, invalidating prior sessions.
  • Campus scope is derived from the authenticated account.
  • Message aliases are stored at send time so future alias rotation can preserve historical conversation context.

Matching (Stage 6)

The foundation creates activity requests, anonymous applications, and acceptance in one transaction. Acceptance creates a match record, private room, marks other applicants waiting, and creates two pending identity-reveal consent records.

Still required: complete API/UI wiring, private-room messages, mutual reveal response, cancellation, outing completion/no-show flow, and two-user end-to-end tests.

Local operation

The running workspace address is http://localhost:3002. Use Docker Compose for local Postgres/Redis, migrate and seed Prisma, build, then run PORT=3002 npm start.
